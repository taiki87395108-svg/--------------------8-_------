## 2. 出力ファイル
`…\word\chapters\row{N}.json`（N＝本文の外側の表の行番号 0〜11）。形式：
```json
{"row": 0, "title": "1．事業者の概要（現状分析・経営課題）", "blocks": [ ... ]}
```
- title は様式の章見出しそのまま：0「1．事業者の概要（現状分析・経営課題）」1「１‐１現状分析」2「１‐２経営課題」3「１‐３省力化補助金活用の動機・目的」4「２. 省力化投資の具体的内容（投資全体金額と補助申請金額を含む）」5「２-１ 省力化設備導入による業務プロセスや配置のビフォーアフター」6「２-２ 省力化投資により期待される効果と事業者全体への波及効果」7「３. 省力化投資で生まれる経営資源の活用による新たな付加価値の創出」8「３‐１ 労働生産性と１人当たり給与支給総額の向上」9「４. 財務計画(資金調達と今後の数値計画)」10「５. 事業の実施体制とスケジュール」11「６. 補足事項」
- 書いたら Python で json.load できることを確認し、本文の文字数（全ブロックのtext＋表セルの合計、改行除く）を数えて報告する。

## 3. ブロックの種類
| t | 用途 | 例 |
|---|---|---|
| "h2" | 章内の小見出し（青太字）。①②③… | {"t":"h2","text":"① SWOT分析"} |
| "h3" | 小々見出し（青太字）。〔 〕・■・【 】 | {"t":"h3","text":"〔製造ラインの構成〕"} |
| "p" | 本文段落（先頭1字下げは自動。行頭に空白を入れない） | {"t":"p","text":"当社は…である。"} |
| "pn" | 字下げしない段落（▶・●・(1)・a)・※ で始まる行や、表の直後の一言） | {"t":"pn","text":"▶ …"} |
| "bullets" | 箇条書き（mark＝"・"/"●"/"▶"。2行目以降はぶら下げ） | {"t":"bullets","mark":"●","items":["…","…"]} |
| "table" | 表（下記） | |
| "labeled" | 左に見出し列がある2列の表（ニッポンジーン様の「経営理念／経営戦略…」の縦見出し表）。右セルの中にブロックを入れ子にできる | {"t":"labeled","label_width":2.4,"items":[{"label":"経営理念","blocks":[...]}]} |
| "img" | 図（中央）。width はcm（最大19.0）。caption は図の上に太字9ptで出る | {"t":"img","src":"fig_v3_s7.png","width":19.0,"caption":"【パウチ供給工程のビフォーアフター（1日あたりの人手作業時間）】"} |
| "note" | 注記（9pt・灰色） | {"t":"note","text":"※…"} |
| "space" | 小さな空き（4pt） | {"t":"space"} |

### table の書き方
```json
{"t":"table",
 "widths":[3.0, 5.0, 11.0],          // 列幅cm。合計は 19.2 以内（labeled の右セル内なら 16.5 以内）
 "header":["項目","内容","備考"],      // 見出し行（紺塗り・白太字）。不要なら null
 "rows":[["…","…","…"], ...],        // セル内の改行は \n
 "align":["center","left","right"],  // 列ごと（省略時 left）
 "bold_first_col": true,              // 1列目を太字に
 "total_row": false,                  // 最終行を太字＋薄い灰塗りに
 "fills": {"1,0":"E2EFDA"},           // "行,列"（0始まり、見出し行は含めない）→塗り色
 "row_fills": {"2":"FCE4E4"},         // 行全体の塗り
 "col_fills": {"0":"DBE5F1"},         // 列全体の塗り
 "font": 9,
 "merge": [[0,0,0,2]]                 // [行,列,行,列] の範囲を結合（任意）
}
```
- 色の目安（ニッポンジーン様準拠）：強み・S×O・AFTER＝E2EFDA（薄緑）、弱み・W×O＝FCE4E4（薄赤）、機会・S×T＝DDEBF7（薄青）、脅威・W×T＝FFF2CC（薄黄）、見出し列＝DBE5F1、合計行＝D9D9D9、外側ラベル（内部環境／外部環境）＝595959＋白文字（"fills" と同時に "<w>…</w>" で白文字にする）。

## 4. 文中の装飾タグ（text・表セル共通）
`<b>太字</b>`　`<r>赤太字（ボトルネック・削減量・重要数値）</r>`　`<blue>青太字（成長率・要件の達成）</blue>`　`<u>下線</u>`　`<g>灰色（変化なし）</g>`　`<w>白太字（濃い塗りのセル用）</w>`
- タグは入れ子にしない。多用しない（1段落に1〜2か所まで）。

## 5. 書き方のルール
- 「である調」。1文は60字以内を目安、1段落は1〜2文。主語は「当社」、投資は「本投資／本事業」、設備は「パウチ自動供給装置」。
- 章の冒頭に「この章で何をするか」を1文で宣言する（ニッポンジーン様の型）。
- 数値は fact_sheet と merged_h.json に完全一致。推測で数字を作らない（四則演算の派生は検算して使ってよい）。
- 専門用語は初出で言い換え（マガジン（製袋機の投入口）、スパウト（キャップ付きの注ぎ口）、製袋機（既設SPM機。空パウチにスパウトを熱圧着する機械）、OEM／ODM 等）。
- SWOT の記号（S1〜S4、W1〜W4、O1〜O4、T1〜T4）と課題①〜④・ボトルネックB1〜B3 は **1-1 で定義した後**に使う（1．事業者の概要では使わない）。伏線回収は「（W1を克服し、O1をつかむ）」の形で。
- merged_h.json にある「（要確認）」は、クライアント確認待ちの印としてそのまま残してよい（ただし1章あたり最小限）。【図表】の指示文は Word には書かない（代わりに img ブロックか表にする）。
- 書かないこと：ものづくり補助金・辞退、不良率・残業時間・派遣費の金額、資金繰りの不安・メインバンク、「増産」（本装置は製袋機の能力150袋／分を上げない。「安定供給・機会損失の防止」と書く）。
- 図（img）の横幅は原則 19.0cm（labeled の右セル内なら 16.0cm 以内）。図の直後に1〜2文で図の読み方を書く。
